必要性檢定—資安與整合

以保留的實體 PBX 為風險基準（SIP UDP 5060 明文、不支援 TLS 1.3）。對等可替換的 IP 替代方案上做兩個耦合單尾 t 檢定；資安與整合兩面向皆拒絕時才拒絕聯合 H0。

為何「保留 PBX」才是風險

  • SIP 預設以 UDP 5060 明文傳輸，除非改用 TLS 5061 + SRTP，否則 INVITE/REGISTER 與 RTP 媒體在路徑上可被讀取。 [TelcoBridges — SBC TLS/SRTP]
  • 舊型 IP-PBX、類比轉接器與舊 SIP 話機僅支援明文 RTP 與 1.3 以前的 TLS（1.0/1.1）—— 即不支援 TLS 1.3。EOS／SOL 等線路以明文傳訊。 [LiveKit — Understanding TLS in SIP]
  • 暴露的 SIP 埠數分鐘內即被 SIPVicious 等免費工具指紋掃描與暴力破解；SS7／SMS 攔截為已知旁路。 [TelcoBridges — VoIP security]

整合難度（異質廠商）

目標 IP 協定本身整合摩擦低（平均摩擦指數 1.08/10）；真正成本在於對舊廠商的一次性橋接。

  • 跨廠商 SIP 因 OEM 各自微調而出問題：專有標頭欄位與非 RFC 訊息序列，運營商 SBC 預設無法處理。 [ClearlyIP — multi-PBX guide]
  • 思科 CUCM 需逐型技術文件處理 SIP 呼叫建立的 RFC 相容性問題。 [Cisco — CUCM interop technote]
  • 松下無法保證所有環境下 SIP 分機運作；舊 PBX 採專有封閉架構，第三方整合成本高 —— 屬一次性橋接成本，非終態障礙。 [VitalPBX — PBX integration]

假設

  • (A) 資安必要性—H0：平均 security_score ≤ 3.0（舊式明文 PBX，不支援 TLS 1.3）；H1：> 3.0。
  • (B) 整合可行性—H0：平均複雜度 ≥ 5（偏高）；H1：< 5。
  • 兩面向皆拒絕方拒絕聯合 H₀，α = 0.05。

檢定母體：53 個可連網（IP）替代方案，與 PBX 訊號等價可替換；另有 78 個實體／本地匯流排方案以隔離防護（平均分數 3.72），非網路加密，另行列示。
