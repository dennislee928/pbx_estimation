SIM & Cellular Connectivity Evolution

How embedded identity is moving from removable cards to fully software-defined SIMs — and why it matters for SIM-bearer PBX, UCaaS, and IoT voice endpoints. 8 technologies and specifications, including 2 GSMA standards.

Technology & Specification Cards

eSIM (Embedded SIM)

Mainstream

Discrete eUICC chip soldered to the motherboard (~6x5 mm), no removable slot

An embedded chip that replaces the removable plastic SIM. Profiles are downloaded and switched remotely (Remote SIM Provisioning), but it still occupies a dedicated area on the board.

Power
Baseline
Footprint
~30 mm²
Security
Dedicated tamper-resistant Secure Element
Adoption
Widely adopted today across consumer and IoT devices
#esim#euicc#hardware#rsp#consumer#iot
Specs
  • GSMA SGP.21/SGP.22 (consumer)
  • GSMA SGP.01/SGP.02 (M2M)
Use cases
  • Smartphones
  • Tablets
  • Wearables
  • Connected cars
  • IoT modules

PBX / voice relevance: Cellular-bearer failover and primary WAN for SIM-based VoIP gateways, mobile UCaaS clients, and fixed-wireless PBX trunks.

iSIM (Integrated SIM)

Emerging

SIM function integrated directly into the device SoC (<1x1 mm), no separate chip

Integrates SIM functionality into the main processor's secure enclave. Uses up to 70% less power and frees board space, leveraging the processor's Trusted Execution Environment (TEE).

Power
Up to 70% lower than eSIM
Footprint
~1 mm²
Security
TEE inside the SoC — higher tamper resistance
Adoption
Ramping: ~0.8M devices in 2024, projected >10M in 2026, 211.8M active by 2028
#isim#soc#tee#hardware#iot#miniaturization#low-power
Specs
  • GSMA SGP.41 (architecture)
  • GSMA SGP.42 (remote provisioning)
  • GSMA SGP.32 (IoT RSP)
Use cases
  • Wearables
  • Medical implants
  • Micro sensors
  • Industrial IoT
  • Asset trackers

PBX / voice relevance: Enables ultra-compact always-connected endpoints (badges, sensors, panic buttons) that register to cellular voice/data without a board-level SIM, decades-long battery telemetry for remote PBX sites.

SoftSIM / vSIM (Software / Virtual SIM)

Frontier

No dedicated hardware — SIM runs as software in the application processor / modem general memory

The most de-hardwared direction: removes all SIM hardware dependency, running credentials purely as a software library with cloud-based dynamic download and management. Eliminates SIM-related BOM cost entirely.

Power
No SIM hardware draw
Footprint
~0 mm²
Security
No dedicated SE — relies on TEE + cloud attestation (historically debated)
Adoption
Early commercial pilots; security model maturing via TEE + cloud attestation
#softsim#vsim#software-defined#no-hardware#cloud#tee#iot#bom-reduction
Specs
  • Vendor-driven (Onomondo, Telna)
  • Leverages GSMA SGP.32 RSP architecture
Use cases
  • Ultra cost-sensitive IoT
  • Extreme miniaturization
  • High-volume disposable trackers

PBX / voice relevance: Zero-BOM cellular identity for disposable / high-volume voice-enabled IoT and field gateways, cloud-managed fleet provisioning aligns with UCaaS / RAG-driven catalog automation.

GSMA SGP.32 (IoT eSIM / RSP)

Standard / Spec

Specification — unifies M2M and consumer eSIM remote provisioning for IoT

GSMA's IoT eSIM specification. Lets iSIM and eSIM share the same Remote SIM Provisioning (RSP) architecture via an eSIM IoT Manager (eIM), drastically cutting global deployment complexity and enabling operator switching at IoT scale.

N/A (specification)
Footprint

Security
Defines secure eIM-based profile management without SMS dependency
Adoption
2025-2026 industry focus shifting from manufacturing to SGP.32 compliance & interoperability certification
#spec#gsma#rsp#iot#eim#interoperability
Specs
  • GSMA SGP.31 (architecture)
  • GSMA SGP.32 (technical)
Use cases
  • Massive IoT fleets
  • Multi-operator IoT
  • Logistics & metering

PBX / voice relevance: Software-defined, SMS-free provisioning is the enabler for fleet-managed cellular voice endpoints and is the key that unlocks iSIM/SoftSIM at scale.

GSMA SGP.41 / SGP.42 (iSIM)

Standard / Spec

Specification pair — iSIM architecture (41) and iSIM remote provisioning (42)

The standards purpose-built for iSIM. SGP.41 defines the iSIM architecture; SGP.42 defines remote provisioning. Together they replace SMS-based legacy flows with efficient, secure profile activation through the eIM.

NTN (Non-Terrestrial Networks / Direct-to-Cell)

Emerging

Network architecture — native satellite support folded into new SIM profiles

With Direct-to-Cell satellite connectivity rising, new SIM specs add native satellite support. iSIM/SoftSIM can seamlessly hand over between terrestrial and non-terrestrial networks without reconfiguration.

Power
Device-dependent
Footprint
—
Security
Inherits SIM credential security across bearers
Adoption
Active rollout via satellite operators and carrier Direct-to-Cell partnerships
#ntn#satellite#direct-to-cell#coverage#3gpp#resilience
Specs
  • 3GPP Release 17/18 NTN
  • Direct-to-Cell initiatives
Use cases
  • Remote/rural coverage
  • Maritime & aviation
  • Disaster resilience
  • Off-grid IoT

PBX / voice relevance: Guarantees voice/SMS reachability for distributed and off-grid PBX sites where terrestrial PSTN/IP backhaul is unavailable, a non-PSTN command path for resilient dispatch.

5G-Advanced (5.5G)

Emerging

Network generation — SIM takes on dynamic slicing & richer authentication roles

Under 5G-Advanced the SIM handles more complex identity duties, including dynamic permissions for Network Slicing, positioning the SIM as a key to multi-dimensional network access rather than just authentication.

Power
Network-dependent

Specs
  • 3GPP Release 18+
Use cases
  • Network slicing for QoS-critical voice
  • Enterprise private 5G
  • Mission-critical comms

PBX / voice relevance: Dedicated network slices can guarantee call-quality SLAs for enterprise UCaaS and contact-center voice over private/public 5G, SIM-bound slice permissions enforce tenant isolation.
